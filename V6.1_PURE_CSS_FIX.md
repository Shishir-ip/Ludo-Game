# Ludo v6.1 - Pure CSS Layout Fix

## Problem
After v6, the board SVG was not rendering - showing a blank game screen. Root cause: JavaScript-computed pixel sizes producing 0, negative, or NaN dimensions, plus CSS depending on JS-set variables without fallbacks.

## Solution
Removed ALL JS-driven sizing and re-implemented the layout in pure CSS.

## Changes Made

### 1. Removed Fragile JS Code
**File: `src/components/GameScreen.tsx`**

- ❌ Removed `podSize` state and `setPodSize` function
- ❌ Removed `boardZoneRef` and all `getBoundingClientRect()` calls
- ❌ Removed `useEffect` that calculated pod size and set `--pod` CSS variable
- ❌ Removed `POD_SLOTS` constant and conditional pod rendering in gutters
- ❌ Removed `DicePod` component (now using floating pod)

### 2. Implemented Pure CSS Layout
**File: `src/index.css`**

```css
#screen-game {
  height: 100dvh;
  overflow: hidden;
  --pod: clamp(56px, 17vw, 84px);  /* CSS default, no JS needed */
  --gutter: calc(var(--pod) + 12px);
  display: grid;
  grid-template-rows: 48px var(--gutter) 1fr var(--gutter) env(safe-area-inset-bottom);
  padding-top: env(safe-area-inset-top);
}

@media (orientation: landscape) {
  #screen-game {
    --pod: clamp(48px, 17vh, 72px);
  }
}
```

**Key improvements:**
- `--pod` has a CSS default value with `clamp()` - no JS fallback needed
- `--gutter` calculated purely in CSS
- Board size emerges from `1fr` + `aspect-ratio: 1/1` - no JS calculation
- Landscape mode uses viewport height instead of width

### 3. New Layout Structure

```
#screen-game (grid)
├── .top-bar (48px) - menu + sound
├── .playfield (grid-row: 2/5)
│   ├── .gutter (top) - turn banner
│   ├── .board-zone (1fr) - board SVG
│   ├── .gutter (bottom) - chips + hint
│   └── .dice-pod (absolute) - floating dice
└── safe area padding
```

### 5. Visibility Guard

**File: `src/components/GameScreen.tsx`**

```typescript
useEffect(() => {
  const checkBoard = () => {
    const svg = boardRef.current?.querySelector('svg');
    const screenGame = document.getElementById('screen-game');
    if (svg && screenGame) {
      requestAnimationFrame(() => {
        if (svg.getBoundingClientRect().width < 120) {
          screenGame.classList.add('layout-fallback');
          console.error('[ludo] board too small → fallback');
        } else {
          screenGame.classList.remove('layout-fallback');
        }
      });
    }
  };

  checkBoard();
  window.addEventListener('resize', checkBoard);
  window.addEventListener('orientationchange', checkBoard);
  return () => {
    window.removeEventListener('resize', checkBoard);
    window.removeEventListener('orientationchange', checkBoard);
  };
}, []);
```

**File: `src/index.css`**

```css
#screen-game.layout-fallback .board-zone svg {
  width: min(94vw, 62dvh);
  height: auto;
}
```

**Purpose:** Belt-and-braces fallback for edge cases where board might be too small.

### 6. Board SVG Sizing

**File: `src/index.css`**

```css
.board-zone svg {
  height: 100%;
  width: auto;
  max-width: 100%;
  aspect-ratio: 1/1;
  display: block;
  filter: drop-shadow(0 20px 40px rgba(0,0,0,0.4));
}
```

**Key points:**
- Board uses `viewBox` only (set in Board.tsx)
- No JS sets `width` or `height` attributes
- Size emerges from CSS: `1fr` row + `aspect-ratio: 1/1`
- `max-width: 100%` prevents overflow
- `display: block` removes inline spacing

**File: `src/components/Board.tsx`**

These scale proportionally with the board via the SVG `viewBox`.

## Why This Fixes the Blank Board

### Before (v6 - Broken)
```typescript
// JS-driven sizing
useEffect(() => {
  const rect = boardZoneRef.current.getBoundingClientRect();
  const boardSize = Math.min(rect.width, rect.height);
  const pod = Math.min(84, Math.max(56, boardSize * 0.17));
  setPodSize(pod);
  document.documentElement.style.setProperty('--pod', `${pod}px`);
}, []);
```

**Problems:**
1. `boardZoneRef.current` might be `null` on first render
2. `getBoundingClientRect()` might return 0 if element not laid out yet
3. `boardSize * 0.17` could be 0, negative, or NaN
4. CSS `calc(var(--pod) + 12px)` fails if `--pod` not set
5. Entire layout collapses if JS fails

### After (v6.1 - Fixed)
```css
/* Pure CSS sizing */
#screen-game {
  --pod: clamp(56px, 17vw, 84px);  /* Always has a value */
  --gutter: calc(var(--pod) + 12px);
  grid-template-rows: 48px var(--gutter) 1fr var(--gutter) env(safe-area-inset-bottom);
}

.board-zone svg {
  height: 100%;
  aspect-ratio: 1/1;
}
```

**Benefits:**
1. `--pod` has a CSS default via `clamp()` - always valid
2. Board size from `1fr` + `aspect-ratio` - no JS needed
3. Layout works even if JS fails
4. No `getBoundingClientRect()` in layout code
5. Visibility guard is optional fallback, not required

**Solution:** Pure CSS layout with CSS custom property defaults
